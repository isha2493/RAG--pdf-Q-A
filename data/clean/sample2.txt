## CHAPTER 1

## INTRODUCTION

In order to guarantee code quality, maintainability, teamwork, and the long-term success of software projects, refactoring of code and documentation are essential procedures in contemporary software development. Appropriate documentation facilitates maintenance, effectively onboards new developers, and acts as a living reference for comprehending intricate code logic. Pull request validation and standards enforcement are two examples of code refactoring-related practices that support development best practices, encourage knowledge sharing, and assist in finding bugs early.

Due to strict deadlines, developer fatigue, and the propensity to concentrate on coding rather than other duties, these tasks are frequently deprioritized despite their significance. When developers are the only ones in charge of documentation and refactoring of code, serious problems occur. Particularly when pressed for time, manual code refactoring can be hurried, biased, or inconsistent. Because it takes more work and produces no results right away, documentation is usually out-of-date or lacking. It gets harder to maintain uniform standards and visibility across codebases as software projects grow in size, which leads to technical debt, onboarding difficulties, and decreased transparency.

This project suggests an autonomous agent for code project management, refactoring of code, and documentation in order to address these problems. By examining the programmer's actual code, this AI-powered system is intended to help with or completely automate these crucial tasks. The system can create thorough documentation and perform intelligent code refactoring by utilizing intelligent planning agents and large language models. While maintaining high standards of software quality and organization, this method not only guarantees accuracy and consistency but also lessens the manual workload on developers, freeing them up to concentrate on solving complex problems.

## 1.1 Background

With the increasing complexity and collaboration of software systems, there is a greater need than ever for efficient and consistent refactoring of code and documentation. Developers have historically handled these responsibilities by hand, which frequently leads to inconsistent work, human error, and out-of-date or inadequate documentation—especially when deadlines are short. Refactoring of code is crucial for finding errors, maintaining coding standards, and preserving code quality, while documentation guarantees dependability, knowledge transfer, and long-term maintainability. Many of these time-consuming and error-prone procedures can now be automated thanks to recent developments in artificial intelligence, especially large language models and autonomous agent frameworks. AI systems can conduct intelligent refactoring of code checks and produce clear, correct documentation by examining the actual code that developers write. This improves the software development lifecycle's accuracy, consistency, and general quality while decreasing the manual workload for developers.

## 1.2 Motivation

Our main motivation lies in making documentation easier for programmers so that this part doesn't just get shelved for long time period but rather goes along side programming. Developers frequently put feature delivery ahead of necessary but time-consuming tasks like refactoring of code and documentation in the fast-paced world of software development. This results in problems like undiscovered bugs, inconsistent standards, out-of-date documentation, and inadequate coordination. The project intends to address this by creating an AI-powered autonomous agent that examines developer code to manage refactoring of code checks automatically and produce precise documentation. We aim to provide an AI powered tool that will ensure all the codes are documented and reviewed correctly. Developers can concentrate on resolving intricate issues while upholding high standards of quality throughout the development lifecycle by minimizing the manual workload.

## 1.3 Statement of the Problem

Despite being crucial elements of the software development lifecycle, refactoring of code and documentation are frequently carried out irregularly or completely ignored. Because these tasks are usually repetitive, time-consuming, and provide little opportunity for creative engagement, developers tend to put feature development ahead of upholding documentation and quality standards. Undiscovered bugs, poor maintainability, onboarding challenges, and mounting technical debt are some of the issues that result from this. Manually carrying out these duties is also susceptible to bias, human error, and exhaustion, particularly when time is of the essence. Intelligent systems that can reliably and independently carry out these tasks are still lacking, and relatively new despite recent developments in AI. An AI-powered autonomous agent that can analyze developer code to perform refactoring of code and produce accurate documentation with little assistance from humans is therefore desperately needed.

## 1.4 Project objective

To create an AI-powered autonomous agent that automates code refactoring and documentation by analyzing code written by developers.

## 1.5 Significance of the study

This study is important because it tackles a prevalent issue in current software development, the manual and uneven management of documentation and refactoring of code. The study provides a solution that lowers human error, saves development time, and guarantees consistent software quality by creating an AI-powered autonomous agent that can intelligently analyze developers' code to automate these tasks. It promotes long-term code maintainability, speeds up onboarding, and improves team collaboration all of which lead to more dependable and effective software development processes. The study makes these simple yet important tasks easier so that they can be done on time and ultimately make things easier for the programmer and cost-effective too.

## LITERATURE REVIEW

Software startups operate in dynamic and tightly constrained environments that need to innovate quickly and with limited resources. Moreover, they face unique challenges in how to manage their development process [1].

Code refactoring remains a challenge for developers, to improve code efficiency and quality. While code refactoring agents like IntelliJ IDEA and JDeodorant exist for intelligent refactoring, detailed refactoring parameters still need to be implemented. This poses a challenge to developers, requiring additional time constraints and expertise. In this context as an alternative, Large Language Models (LLMs) like GPT-4 demonstrate high functionality, especially in solving complex problems. LLMs possess the potential to autonomously identify refactoring opportunities. However, without clear and concrete guidance, LLMs may struggle to accurately pinpoint such opportunities [2].

As a solution to generic LLMs and their limitation, work has been done in increasing capabilities of LLMs in low resource settings through composition and finetuning. Recent work has explored transformer-based deep learning architectures to automate code review activities, including recommending code changes to contributors and generating code from reviewer comments, achieving promising results with meaningful recommendations in up to 16% and 31% of cases respectively, although further improvements are necessary for practical adoption by developers [3].

In code review tasks, LLaMA-Reviewer, a framework that combines the LLaMA large language model (LLM) with parameter-efficient fine-tuning (PEFT) methods such as Low-Rank Adaptation (LoRA), has shown exceptional performance. Even with little tuning, LLaMA-Reviewer performed better on the CRer dataset than all baseline models, including those specially pre-trained for code review [4].

Identifying the lines of code that are most likely to cause issues is another way to increase the effectiveness of code reviews. By anticipating lines that will be revised or receive reviewer comments, REVSPOT, a machine learning-based method, tackles the laborious nature of manual code review.

===== PAGE 12 =====
When tested on three open-source projects (OpenStack Nova, OpenStack Ironic, and Qt Base), REVSPOT outperformed baseline techniques with a Top-10 Accuracy of 81% for comment prediction and 93% for revision prediction. Our approach, on the other hand, is intended to function in lowresource or startup environments where such data might not be available. Rather than relying on large historical review logs, we use a lightweight, modular, LLM-powered multi-agent framework that uses composition techniques like LoRA and prompt tuning to enable the system to generalize across projects [5].

Fine-tuning all parameters of LLMs requires significant hardware resources, which can be impractical for typical users. As a workable substitute for complete fine-tuning, Low-Rank Adaptation (LoRA) has emerged as one of the most popular methods for Parameter Efficient Fine-Tuning (PEFT) of Large Language Models (LLMs). With average gains of 34 and 10 points, respectively, across 10 base models and 31 tasks (310 total combinations), recent work has shown that 4-bit LoRA-fine-tuned models can outperform both base models and GPT-4 in the context of real-world deployment across a wide range of tasks. Additionally, LoRA facilitates effective resource utilization: By sharing base weights and dynamically loading adapters, LoRAX, an open-source Multi-LoRA inference server, makes it possible to deploy multiple LoRA-fine-tuned models on a single GPU [6].

Distributed decision-making and cooperative problem-solving are ideal applications for multi-agent systems (MAS), where system structure is crucial to agent interaction. Agents in LLM-based MAS assume specialized roles to manage challenging tasks, mainly depending on internal communication to share evaluations, contextual signals, and status updates. Throughout the system, this interaction promotes coherence, coordination, and adaptability. In dynamic environments and hierarchical task execution, where agents are constantly improving their behavior to improve system performance, this kind of communication is especially important. Thus, MAS frameworks provide modular and scalable solutions for intricate real-world applications [7].

Multi-Agent LLM systems have been worked upon to build documentation and review systems. A multi-agent LLM-based system called Code Agent was created to model cooperative team dynamics in code reviews. In contrast to conventional single-model approaches, Code Agent’s four-phase process—Basic Info Sync, Code Review, Code Alignment, and Documentation—defines distinct

===== PAGE 13 =====
roles, including Reviewer, CTO, and QA-Checker. Agents have structured, instruction-following conversations during each phase. One noteworthy invention is the QA-Checker, a supervisory agent that fixes the problem of prompt drifting in multi-agent communication by guaranteeing prompt coherence and task focus. With up to 93% Top-10 Accuracy in comment prediction and a 30% improvement in code edit progress metrics, Code Agent outperformed GPT-4 and other models in tasks like vulnerability detection, code-style consistency, and code revision [8].

Another agent, Repo Agent is an open-source framework that uses large language models to generate code documentation at the repository level. Repo Agent examines the global structure of repositories to produce thorough, semantically coherent documentation, in contrast to earlier methods that concentrated on function-level or class-level summaries. Documentation Generation through structured prompts, Documentation Update through Git hooks for real-time synchronization with code changes, and Global Structure Analysis through AST and reference relationships are its three main components. With preference rates of 70% and 91% on real-world repositories, Repo Agent performs better in blind preference tests than human-authored documentation. Additionally, it exhibits accurate parameter detection and high recall for reference identification. Thus, Repo Agent shows how useful and efficient LLMs are at keeping accurate and current project documentation, which makes it especially appropriate for low-resource environments where manual documentation is timeconsuming [2].

## CHAPTER 5

## METHODOLOGY

## 5.1 System Overview

The platform is built as a web application, functioning with a complete stack-based system. The platform hosts multiple agents and follows a modular microservice architecture. The multiple agents control different functionalities, and are integrated into a unified platform built on the MERN stack (MongoDB, Express.js, React.js, Node.js) for frontend and backend, while the multi-agent system is built upon Lang graph and Crew AI. Communication between the modules is to be done using REST APIs and asynchronous message queuing.

## 5.2 Input Message Processing

The user is able to input code into a sandbox environment on the platform. The code first goes through a parsing and preprocessing step when a user submits it to the platform, whether for planning, testing, review, or documentation. The system examines the input's syntactic and semantic structure using a specialized code parser. Abstract syntax trees (ASTs), method signatures, and metadata like variable types, function calls, and dependencies are all extracted during this parsing process. The downstream agents can efficiently consume and interpret the code using a uniform interface made possible by the structured representation. Relevant agents then take over the processing duty to orchestrate the functions.

## 5.3 Multi-Agent Architecture

The platform is designed to facilitate multiple agents that perform code refactoring and code documentation. The agents are LLM-powered through a centralized layer that manages task sequencing, data flow, and communication. There are two proposed agents with different functionalities: Refactor Agent and DocAgent.

===== PAGE 22 =====
## 5.4 Agent Creation

Each agent is built as a modular LLM-powered component, which handles a specific part of the platform. The agent is built upon LLaMa models, extended with lightweight task-specific augmentation. Instead of fine-tuning the base model, we use a composition-based approach, where agents are built using frozen LLaMA weights and new behavior is injected using auxiliary control modules, low-rank adapters (LoRA), or prompt engineering. The three main components of each agent are a task-optimized prompt template, a frozen LLaMA backend for inference, and an execution and inter-agent communication interface that is compatible with Crew AI or Lang Graph. Each agent is built around a particular software engineering task.

## 5.5 Code Specific Context

We build code-specific context for both agents. We use two carefully chosen datasets to train and evaluate our code intelligence agents. The DocAgent is trained using Reviewed Code Pairs (RCP), where each pair <ms, mr> indicates abstracted methods before and after code review. This data allows the agent to learn structural and semantic changes and produce documentation that reflects intent and reasoning.

The Refactor Agent combines the submitted method (ms), its revised version (mr), and natural language reviewer feedback (rnl) using the Reviewed Commented Code Triplets (RCCT) dataset, which is arranged as <rnl, ms, mr>. This triplet structure allows the agent to generate contextual refactoring suggestions based on reviewer code and intent. The two datasets are separated into training (80%), validation (10%), and test (10%).

## 5.6 Communication Among Multiple Agents

To control agent communication and orchestration, the platform uses a centralized coordination layer based on Crew AI and Lang graph. Modular and decoupled execution is made possible by agents' asynchronous operation and interaction through a combination of REST APIs and message queues (such as RabbitMQ or Kafka). Task sequencing is managed by the coordination layer, which makes sure that dependent operations—like creating documentation prior to starting a refactor—are carried out in the right order. To enable consistent and comprehensible communication, agents exchange

===== PAGE 23 =====
structured intermediate data in JSON format, such as parsed code and review comments. With the help of an event-driven messaging system, agents can publish and subscribe to important events (such as "Code Parsed" and "Refactor Completed"), which will start downstream processes without stopping them.
